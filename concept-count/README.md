# Counting what a framework's examples make users write

`count_concepts.py` reads a Python example and reports the framework concepts
it makes its user write, in separate columns:

| Column | What counts |
|---|---|
| Names | names imported from the framework, plus attributes read or called on framework objects |
| Hooks | user functions the framework calls: decorated functions, methods on framework subclasses, functions passed to framework calls, and (with `--hook-prefix`) functions found by name |
| Options | keyword arguments to framework calls, and string keys of dictionaries inside them |
| Strings | string constants of 40 characters or fewer with no whitespace, anywhere in the arguments of a framework call except inside a nested call to non-framework code; and, with `--string-namespace`, attributes read on a namespace that accepts any name (`pytest.mark.<anything>`) |
| Settings | with `--settings`: module-level UPPER_CASE names, for frameworks that read a settings module by name |
| Import paths | strings anywhere in the file that look like dotted import paths with three or more parts (`package.module.Name`) |

Only names make the headline number. The other columns are different kinds of
thing to learn, so they stay separate.

## Run it on your own quickstart

Python 3.9 or later, no dependencies.

```sh
python3 count_concepts.py yourframework quickstart.py
python3 count_concepts.py pytest conftest.py --hook-prefix pytest_ --string-namespace mark
python3 count_concepts.py django settings.py --settings
```

The first argument is your framework's top-level package name (comma-separate
several). The output lists every counted item, so you can check and correct it.

## Reproduce the article's numbers

```sh
python3 run_comparison.py            # fetch the pinned examples and print the table
python3 run_comparison.py --detail   # also list every counted item
python3 -m pip install -r requirements.txt
python3 typo_checks.py               # misspell one concept at a time
```

`run_comparison.py` downloads each example in `sources.json` from GitHub at a
pinned commit, caches it in `.cache/`, and writes `results.json`.
`typo_checks.py` runs six misspellings against the pinned Django, pytest and
FastAPI releases and prints when each one is caught. The Django cases use a
project generated by `startproject` and Django's own `manage.py check`.

## Limits

- Tracking is flow-insensitive and syntactic. A variable counts as a framework
  object if it is imported from the framework, assigned from an expression
  rooted in one, annotated with a framework type, or a parameter of a function
  found by `--hook-prefix`. Objects that reach the example another way are
  missed, and a name reused for two things is counted once.
- Every method on a subclass of a framework class, other than `__init__`, counts
  as a hook, whether or not the framework calls it. Functions the framework finds
  by name are missed unless you pass their prefix.
- Members are a set of attribute names, so the same attribute read on two
  different framework objects (`x.start`, `y.start`) counts once.
- A keyword argument with a string value counts twice, once in each column:
  `model="nova-3"` adds `model` to options and `"nova-3"` to strings.
- Concepts delivered by naming conventions other than settings and hook
  prefixes, such as a web framework matching a path parameter to a function
  parameter by name, are not counted. Read the framework's docs for those.
- Import paths with two parts (`mysite.urls`) are missed, to avoid counting
  file names like `data.json`.
- The string and import-path rules are heuristics. Read the detail output and
  correct it for your framework before comparing numbers.
- Counts compare frameworks only for the same task. Pick each framework's
  smallest official example of that task, pinned to a release.
